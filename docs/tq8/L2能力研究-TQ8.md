## 3. 未落盘 L2 面板数据排查(结论)

1. **每档逐笔挂单队列**(谁在什么价位排队、单笔委托明细):.img 仅档位汇总,.tck 无队列维度 → **当前落盘体系拿不到**。若需,唯一通道=盘中实时订阅(subscribe_hq 无队列)或客户端内存抓取(侵入性大,不建议)。
2. **委托↔成交显式关联**:.tck 三类记录共用全市场消息序号空间(0~5,090 万/日),成交记录未携带委托归组键(98,088 笔序号全唯一零复用) → **委托级还原(一笔委托拆 N 笔成交的精确聚簇)当前拿不到**,已列 TQ4 后续研究。撤单目标槽位二义性同源。
3. **主力监控精灵信号流**:不落盘(手册已确认),本机同;darkflow 规则近似(已落地)。
4. 其余 L2 面板数据(十档/逐笔/撤单)**全部有落盘对应**——超盘回放已把 L2 核心数据落全。

## 5. 对三指标的影响(增量)

1. 暗盘资金主通道已闭环(.tck→darkflow→MI1 托盘规则吃到真分档)。
2. **委托级还原是下一个精度跃迁**(Hermes 已定性"精确一个量级"):打通后 明盘=还原后单笔≥30万/100万净额、暗盘=小单净额(拆单部分),同花顺黑盒核心即此。
3. 买卖队列拿不到 → 盘口意图类信号(挂撤蓝子/队列异动)在落盘体系内做不了,只能盘中实时(且 subscribe_hq 无队列)——建议三指标体系不依赖队列级信号,以十档+分档+撤单率(撤单量/委托量,可从 .tck 自建)为主。
4. 新可自建指标候选:**撤单率**(SCancel+BCancel 消息序号差分/时序)与**撤单方向比**——暗盘资金的强补充维度,.tck 数据已支持。
